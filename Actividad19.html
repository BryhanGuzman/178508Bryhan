01 / INTRODUCCIÓN

La primera respuesta define la evidencia disponible.

La práctica simula la intervención de un investigador forense digital ante un equipo Windows comprometido y encendido. El propósito es documentar la información disponible mediante comandos del sistema, antes de que los datos volátiles cambien o desaparezcan.

01

Información del sistema

Fecha, hora, procesos, servicios, usuarios y características del equipo.

02

Actividad de red

Adaptadores, conexiones, puertos, nombres NetBIOS, caché DNS, ARP y redes Wi-Fi.

03

Artefactos y registros

Historial de comandos, recursos compartidos, tareas programadas, eventos y archivos del sistema.

Alcance: el reporte presenta salidas de comandos y su importancia forense; la presencia de un proceso, servicio o conexión no confirma por sí misma actividad maliciosa.
02 / PROCEDIMIENTO

Veinte actividades de adquisición

El informe documenta veinte consultas y capturas realizadas sobre el sistema Windows. Se agrupan aquí para facilitar su lectura dentro del portafolio.

SISTEMA, PROCESOS Y USUARIOS · 01–05
01

Fecha y hora del sistema

Get-Date

Se estableció una referencia temporal para relacionar los acontecimientos investigados.

02

Procesos en ejecución

tasklist

Se registraron los procesos activos para revisar programas o ejecuciones desconocidas.

03

Servicios del sistema

sc query / Get-Service

Se compararon CMD y PowerShell: el primero presenta detalles técnicos y el segundo una tabla que facilita el filtrado.

04

Usuarios conectados

NetUsers.exe

Se consultaron sesiones de usuario activas mediante la utilidad proporcionada para la práctica.

05

Cuentas del equipo

net user

Se enumeraron cuentas locales; este listado no demuestra por sí solo inicios de sesión históricos.

RED Y COMUNICACIONES · 06–12
06

Configuración de red

ipconfig /all

Se obtuvo información de adaptadores, direcciones y configuración de conectividad.

07

Nombres NetBIOS

nbtstat

Se revisaron los nombres registrados para identificar referencias de red local.

08

Conexiones de red

netstat -an

Se registraron conexiones y puertos en escucha en formato numérico.

09

Aplicaciones y puertos

netstat -bnoa

Se relacionaron ejecutables, conexiones, puertos y PID.

10

Dominios consultados

ipconfig /displaydns

Se revisó la caché DNS para identificar dominios resueltos recientemente.

11

Relaciones IP y MAC

arp -a

Se consultó la caché ARP para revisar dispositivos detectados en la red local.

12

Perfiles de Wi-Fi

netsh wlan show profiles

Se listaron los perfiles inalámbricos almacenados en el equipo.

ARTEFACTOS Y CONFIGURACIÓN · 13–20
13

Historial de comandos

Get-History

Se recuperaron los comandos disponibles en el historial de la sesión de PowerShell.

14

Unidades del sistema

Get-PSDrive

Se examinaron las unidades y proveedores accesibles desde PowerShell.

15

Recursos compartidos

Get-SmbShare

Se identificaron recursos compartidos, incluidos los administrativos.

16

Información del equipo

Get-ComputerInfo

Se documentaron características del sistema operativo y del dispositivo.

17

Tareas programadas

Get-ScheduledTask

Se enumeraron tareas que podrían iniciar procesos automáticamente.

18

Registros del sistema

wevtutil epl

Se exportaron registros de eventos para su análisis posterior.

19

Archivo hosts

Get-Content hosts

Se consultó el archivo hosts para revisar asignaciones locales de nombres.

20

Archivos por fecha de creación

Get-ChildItem / Sort-Object CreationTime

Se ordenó el listado de archivos por fecha de creación para buscar elementos de interés.

SERVICIOS

Comparación CMD y PowerShell

CMD presenta datos técnicos del servicio, mientras que PowerShell ofrece una tabla que facilita la lectura y el filtrado de los resultados.

USUARIOS

Sesiones y cuentas

Se utilizó NetUsers.exe para consultar usuarios conectados y net user para listar cuentas locales. Son consultas diferentes y no equivalen a un historial completo de inicios de sesión.

CONECTIVIDAD

Red y puertos

Se obtuvieron detalles de adaptadores y conexiones; netstat -bnoa permitió relacionar aplicaciones y PID con puertos.

REGISTROS

Artefactos de investigación

Se recopilaron tareas programadas, recursos compartidos, registros de eventos y datos del archivo hosts para su revisión posterior.

04 / COMANDOS

Ejemplos de adquisición

Estos ejemplos ilustran comandos utilizados en la práctica. La ruta de salida debe adaptarse al entorno del investigador.

# Hora y procesos
Get-Date | Out-File FechaHora.txt
tasklist > ListaProcesos.txt

# Servicios y usuarios
Get-Service | Out-File ServiciosPS.txt
net user > UsuariosLocales.txt

# Configuración y conexiones de red
ipconfig /all > InfoRed.txt
netstat -an > Conexiones.txt
netstat -bnoa > Puertos.txt

# Evidencia complementaria
Get-History > HistorialComandos.txt
Get-SmbShare > RecursosCompartidos.txt
Get-ScheduledTask > TareasProgramadas.txt
Consideración técnica: algunos comandos requieren permisos elevados; la información capturada depende del equipo, de los privilegios y del estado del sistema al momento de ejecutarlos.

CONCLUSIÓN

La adquisición inicial permite conservar el contexto digital.

La actividad permitió documentar información del sistema, procesos, servicios, usuarios, conexiones y otros artefactos mediante comandos de Windows. El registro organizado de estos resultados facilita el análisis posterior y ayuda a establecer líneas de investigación sin confundir indicadores técnicos con pruebas concluyentes de un incidente.
