Validation of Start of Path.

Laboratorio de File Path Traversal enfocado en una validación insuficiente del inicio de una ruta. La aplicación comprueba que la ruta proporcionada comience con el directorio esperado, pero permite utilizar secuencias de salto de directorio después de dicha ruta.

01
INFORMACIÓN GENERAL

Sobre el laboratorio

Comprobar únicamente el comienzo de una ruta no garantiza que el archivo final permanezca dentro del directorio autorizado.

En este laboratorio, la aplicación transmite la ruta completa de las imágenes mediante el parámetro filename.

Como mecanismo de defensa, comprueba que la ruta suministrada comience con /var/www/images/. Sin embargo, no elimina correctamente las secuencias de salto de directorio introducidas después de esa ruta.

02
ANÁLISIS TÉCNICO

¿Dónde está la vulnerabilidad?

Validar el inicio de la ruta no es suficiente.

La aplicación utiliza el parámetro filename para determinar qué archivo debe recuperar desde el servidor.

Como medida de seguridad, comprueba que el valor recibido comience con el directorio autorizado:

/var/www/images/

El problema es que, después de esta comprobación, todavía es posible agregar secuencias ../.

Estas secuencias permiten retroceder desde el directorio de imágenes hasta alcanzar otras ubicaciones del sistema de archivos.

PROCEDIMIENTO

Desarrollo del laboratorio

El laboratorio se realizó utilizando PortSwigger Web Security Academy y Burp Suite. Se interceptó la petición utilizada para cargar una imagen y posteriormente se modificó el parámetro filename mediante Repeater.

01
ACCESO

Iniciar el laboratorio

Se accede al laboratorio File path traversal, validation of start of path y se selecciona ACCESS THE LAB.

La plataforma genera una dirección URL específica para la instancia del laboratorio.

02
BURP SUITE

Iniciar Burp Suite

Se abre Burp Suite Community Edition, se selecciona Temporary project in memory y posteriormente Use Burp defaults.

03
PROXY

Abrir el laboratorio

Desde la pestaña Proxy se cambia la interceptación y se utiliza Open browser para abrir el navegador integrado de Burp Suite.

En este navegador se introduce la URL generada por Web Security Academy.

04
HTTP REQUEST

Identificar la solicitud de imagen

Dentro del tráfico HTTP se localiza la solicitud correspondiente a una imagen del producto.

GET /image?filename=/var/www/images/42.jpg HTTP/2

La petición seleccionada se envía a Repeater mediante la opción Send to Repeater.

05
EXPLOTACIÓN

Modificar filename

En Repeater se reemplaza la ruta original de la imagen por el payload:

/var/www/images/../../../etc/passwd

Finalmente se presiona Send para enviar la petición modificada.

05
DEFENSA

Mitigaciones recomendadas

01

Evitar rutas directas

No pasar directamente las entradas proporcionadas por el usuario a las APIs encargadas de acceder al sistema de archivos.

02

Lista blanca

Utilizar una whitelist de valores permitidos y aceptar únicamente los caracteres y extensiones necesarias para los archivos esperados.

03

Rechazar secuencias peligrosas

La entrada debe validarse para impedir secuencias especiales utilizadas para navegar entre directorios, como ../.

04

Resolver la ruta absoluta

Utilizar funciones como realpath() para obtener la ruta absoluta y comprobar que la ruta final permanezca dentro del directorio base autorizado.

CONCLUSIÓN

Validar el inicio no garantiza la ruta final.

Este laboratorio demuestra que verificar únicamente que una ruta comience con un directorio autorizado no evita una vulnerabilidad de Path Traversal.

El payload conserva /var/www/images/ al inicio para superar la validación, pero utiliza posteriormente ../../../ para retroceder hasta el directorio raíz y acceder a /etc/passwd.
