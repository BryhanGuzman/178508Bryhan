02
OBJETIVO

¿Qué busca demostrar el laboratorio?

Evadir un filtro utilizando una ruta absoluta

El laboratorio presenta una aplicación vulnerable a File Path Traversal en la carga de imágenes de productos.

A diferencia del caso simple de la actividad anterior, la aplicación bloquea las secuencias tradicionales utilizadas para retroceder directorios.

Sin embargo, el parámetro encargado de seleccionar el archivo continúa aceptando una ruta absoluta, permitiendo solicitar directamente un recurso del sistema operativo.

OBJETIVO DEL LAB

Recuperar

/etc/passwd

El servidor debe devolver el contenido del archivo solicitado utilizando directamente su ubicación absoluta en el sistema.

03
MARCO TEÓRICO

Traversal bloqueado no significa acceso seguro

Bloquear únicamente secuencias como ../ no elimina necesariamente una vulnerabilidad de acceso a archivos.

Una aplicación puede intentar protegerse eliminando o rechazando secuencias utilizadas para subir niveles dentro del árbol de directorios.

El problema aparece cuando el servidor continúa aceptando rutas absolutas introducidas directamente por el usuario.

De esta manera, en lugar de recorrer desde el directorio actual hasta alcanzar el archivo deseado, puede indicarse directamente su ubicación completa.

04
ANÁLISIS TÉCNICO

¿Dónde se encuentra la vulnerabilidad?

SOLICITUD NORMAL 
GET /image?filename=10.jpg HTTP/2
↓
TRAVERSAL TRADICIONAL 
filename=../../../../etc/passwd
La aplicación bloquea las secuencias ../
↓
ABSOLUTE PATH BYPASS 
filename=/etc/passwd
La ruta absoluta continúa siendo procesada.

09
MITIGACIÓN

¿Cómo prevenir este bypass?

01

No confiar en rutas del usuario

La aplicación no debería utilizar directamente rutas recibidas mediante parámetros HTTP.

02

Bloquear rutas absolutas

Las validaciones deben impedir tanto traversal relativo como rutas absolutas externas al directorio permitido.

03

Canonicalización

Resolver la ruta definitiva antes de acceder al archivo y comprobar que permanezca dentro del directorio autorizado.

04

Lista permitida

Limitar los archivos disponibles mediante identificadores o nombres previamente establecidos.

05

Mínimo privilegio

El proceso del servidor web debe tener acceso únicamente a los archivos necesarios.

06

Validación completa

No basta con bloquear una sola representación. Deben validarse todas las formas posibles de indicar una ruta.

10

CONCLUSIÓN

Bloquear un payload no significa corregir la vulnerabilidad

Este laboratorio demuestra que bloquear únicamente las secuencias tradicionales de navegación entre directorios no constituye una defensa suficiente.

Aunque el servidor impida valores que contengan secuencias relativas como ../, la vulnerabilidad continúa existiendo si permite utilizar directamente rutas absolutas para seleccionar archivos.

Una mitigación adecuada debe validar la ruta final, restringir el acceso al directorio autorizado y aplicar controles de permisos en el sistema operativo.
