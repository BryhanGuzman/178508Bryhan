File Extension Null Byte Bypass.

Laboratorio de File Path Traversal enfocado en la evasión de una validación de extensión mediante un null byte. La aplicación exige una extensión de imagen, pero el procesamiento posterior de la ruta permite acceder a un archivo fuera del directorio autorizado.

01
INFORMACIÓN GENERAL

Sobre el laboratorio

Comprobar únicamente la extensión aparente de un archivo puede resultar insuficiente cuando existen diferencias entre la validación de la aplicación y el procesamiento final de la ruta.

El laboratorio presenta una vulnerabilidad de File Path Traversal en la funcionalidad encargada de mostrar las imágenes de los productos.

La aplicación incorpora una validación relacionada con la extensión del archivo. El objetivo consiste en comprender cómo un null byte puede utilizarse para alterar la interpretación de la ruta y acceder al archivo objetivo.

ANÁLISIS TÉCNICO

¿Dónde está la vulnerabilidad?

La extensión válida no garantiza una ruta segura.

La aplicación recibe mediante el parámetro filename el nombre del archivo que desea recuperar desde el servidor.

Como mecanismo de protección, la aplicación comprueba que el valor proporcionado termine con una extensión permitida para las imágenes.

Sin embargo, el laboratorio presenta un escenario donde puede utilizarse un null byte para conseguir que la entrada satisfaga la comprobación de extensión y, al mismo tiempo, que la ruta procesada apunte a un archivo diferente.

PROCEDIMIENTO

Desarrollo del laboratorio

El procedimiento mantiene el flujo utilizado en los laboratorios anteriores: acceder al laboratorio, configurar Burp Suite, analizar el tráfico HTTP, identificar la solicitud de una imagen y modificar el parámetro filename desde Repeater.

01
ACCESO

Iniciar el laboratorio

Se accede al laboratorio File path traversal, validation of file extension with null byte bypass desde PortSwigger Web Security Academy.

Posteriormente se selecciona ACCESS THE LAB para iniciar la instancia correspondiente.

02
BURP SUITE

Preparar Burp Suite

Se inicia Burp Suite Community Edition utilizando un proyecto temporal y la configuración predeterminada.

03
PROXY

Capturar el tráfico HTTP

Desde la pestaña Proxy se utiliza el navegador integrado de Burp Suite para acceder al laboratorio y generar las solicitudes correspondientes a las imágenes.

04
HTTP REQUEST

Identificar filename

En el historial HTTP se localiza una petición encargada de recuperar una de las imágenes mostradas por la aplicación.

GET /image?filename=...jpg HTTP/2

La solicitud se envía a Repeater para poder modificar manualmente su parámetro.

05
EXPLOTACIÓN

Introducir el null byte

Desde Repeater se sustituye el valor original del parámetro filename por:

../../../etc/passwd%00.png

Posteriormente se utiliza Send para enviar la solicitud modificada.

05
DEFENSA

Mitigaciones recomendadas

01

Evitar rutas proporcionadas por el usuario

No utilizar directamente el valor recibido desde el cliente para construir rutas del sistema de archivos. Es preferible trabajar con identificadores internos.

02

Lista blanca

Utilizar una lista de archivos o valores permitidos en lugar de confiar únicamente en la extensión incluida en el nombre solicitado.

03

Normalizar la entrada

La entrada debe ser decodificada y normalizada antes de realizar las comprobaciones de seguridad, rechazando caracteres o secuencias no permitidas.

04

Verificar la ruta final

Resolver la ruta absoluta del archivo y comprobar que permanezca dentro del directorio base autorizado antes de realizar cualquier operación de lectura.

CONCLUSIÓN

Validar una extensión no garantiza una ruta segura.

Este laboratorio permite analizar cómo una validación basada únicamente en la extensión aparente de un archivo puede resultar insuficiente cuando existen diferencias entre la validación de la aplicación y el procesamiento posterior de la ruta.

La combinación de ../../../etc/passwd, el null byte %00 y una extensión permitida demuestra la importancia de validar la ruta final y no solamente el formato del valor recibido.
