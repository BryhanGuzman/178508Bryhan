OBJETIVO

¿Qué busca demostrar el laboratorio?

Evadir una sanitización aplicada de manera no recursiva

La aplicación contiene una vulnerabilidad de File Path Traversal dentro del mecanismo encargado de mostrar las imágenes de los productos.

El servidor intenta protegerse eliminando las secuencias tradicionales de navegación de directorios.

Sin embargo, el filtro solamente revisa la cadena una vez. Esto permite construir un valor que, después de la eliminación parcial realizada por el filtro, vuelve a formar una secuencia válida de traversal.

03
MARCO TEÓRICO

File Path Traversal y Broken Access Control

File Path Traversal permite acceder a archivos arbitrarios del servidor cuando una aplicación no controla correctamente las rutas proporcionadas por el usuario.

El problema se relaciona con Broken Access Control, ya que un usuario consigue acceder a recursos del sistema de archivos que no deberían estar disponibles desde la aplicación.

Desde la perspectiva de la triada CIA, el principal impacto se produce sobre la Confidencialidad, debido a la exposición de información interna o sensible del servidor.

EXPLICACIÓN DEL PAYLOAD

¿Cómo se evade el filtro?

request.http 
GET /image?filename=....//....//....//etc/passwd HTTP/2
....//

La cadena contiene una secuencia de traversal incrustada dentro de más caracteres.

Filtro

El servidor elimina la primera coincidencia de ../, pero no vuelve a procesar el resultado.

../

Después de la eliminación, los caracteres restantes se unen y forman nuevamente una secuencia válida para subir un directorio.

Repetición

Al repetir la técnica varias veces, el laboratorio permite retroceder suficientes niveles para alcanzar el archivo objetivo.

MITIGACIÓN

¿Cómo prevenir esta vulnerabilidad?

01

Evitar rutas proporcionadas por usuarios

No pasar directamente nombres de archivos proporcionados por el usuario a las funciones del sistema de archivos.

02

Allowlisting

Validar el valor recibido contra una lista estricta de archivos permitidos o utilizar identificadores internos.

03

Ruta canónica

Resolver la ruta absoluta final y verificar que permanezca dentro del directorio base autorizado.

04

Validación recursiva

No depender de una sola sustitución de cadenas. La entrada debe validarse completamente antes de utilizarse.

05

Mínimo privilegio

El proceso del servidor debe tener únicamente permisos sobre los recursos que realmente necesita.

06

Separación de recursos

Mantener los archivos públicos aislados de información sensible del sistema operativo.

10

CONCLUSIÓN

Sanitizar una vez no significa validar correctamente

Este laboratorio demuestra que una defensa basada únicamente en eliminar patrones peligrosos puede ser insuficiente cuando el proceso de sanitización no analiza nuevamente el resultado generado.

El payload utilizado aprovecha precisamente esa debilidad: una vez que el filtro elimina una secuencia, los caracteres restantes vuelven a formar un patrón de traversal válido.

El laboratorio también refuerza la importancia de utilizar validación estricta, rutas canónicas, listas permitidas y el principio de mínimo privilegio.
