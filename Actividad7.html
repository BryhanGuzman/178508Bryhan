OBJETIVO

¿Qué busca demostrar el laboratorio?

Acceso a archivos fuera del directorio permitido

El objetivo del laboratorio es identificar una vulnerabilidad de File Path Traversal en una aplicación web que utiliza nombres de archivo proporcionados por el usuario.

Mediante Burp Suite se intercepta una petición HTTP relacionada con la carga de una imagen y posteriormente se modifica el parámetro encargado de indicar el archivo solicitado.

La prueba permite demostrar cómo una validación insuficiente de rutas puede provocar que el servidor entregue archivos que deberían permanecer fuera del alcance del usuario.

03
MARCO TEÓRICO

¿Qué es File Path Traversal?

File Path Traversal es una vulnerabilidad que permite acceder a archivos ubicados fuera del directorio que una aplicación debería permitir.

Normalmente ocurre cuando una aplicación utiliza nombres de archivo enviados por el usuario para abrir o cargar recursos sin realizar una validación adecuada del contenido recibido.

Los segmentos:

../

representan el directorio padre en muchos sistemas. Si una aplicación concatena directamente este valor con una ruta del servidor, es posible recorrer directorios superiores.

EJEMPLO CONCEPTUAL

Solicitud normal:

/show?file=report.pdf

Ruta manipulada:

/show?file=../../../etc/passwd

El ejemplo se utiliza únicamente dentro de laboratorios autorizados y deliberadamente vulnerables.

EXPLICACIÓN TÉCNICA

¿Por qué funciona el payload?

request.http 
GET /image?filename=../../../etc/passwd HTTP/2
../../../

Cada segmento ../ indica al sistema que debe subir un nivel dentro de la estructura de directorios.

/etc/passwd

Corresponde al archivo solicitado como objetivo dentro de este laboratorio específico.

filename

Es el parámetro utilizado por la aplicación para decidir qué archivo debe recuperar.

MITIGACIÓN

¿Cómo prevenir File Path Traversal?

01

Evitar rutas proporcionadas por el usuario

Utilizar identificadores internos en lugar de recibir directamente nombres o rutas de archivos.

02

Validación estricta

Validar los valores recibidos utilizando listas permitidas y reglas definidas por la aplicación.

03

Normalización de rutas

Resolver y verificar la ruta final antes de abrir cualquier archivo.

04

Permisos mínimos

El proceso del servidor debe contar únicamente con los permisos indispensables.

05

Aislamiento

Mantener los archivos públicos separados de recursos sensibles del sistema.

06

Monitoreo

Registrar solicitudes anómalas que intenten utilizar patrones relacionados con navegación de directorios.

09

CONCLUSIÓN

Una ruta manipulada puede convertirse en una fuga de información

El laboratorio permitió comprender cómo una aplicación que utiliza directamente rutas proporcionadas por el usuario puede exponer archivos internos del servidor.

También permitió practicar el uso de Burp Suite para interceptar, analizar y modificar peticiones HTTP dentro de un entorno específicamente diseñado para pruebas de seguridad.

La principal enseñanza es que la validación de entradas, la normalización de rutas y el principio de mínimo privilegio son medidas fundamentales para reducir este tipo de vulnerabilidades.
